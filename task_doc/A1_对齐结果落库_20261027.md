# A1：标准标识符对齐结果落库

> 2026-10-27 · 原链路 `content_cleaner → storage_writer → repository` 为主，新链路（`CollectedDocument → publication`）保留为下游供数旁路

## 一、为什么做

A0.8 结束时药名命中率已到 21/26 = 80.8%，但**对齐结果只存在两类旁路里**：

| 载体 | 内容 | 问题 |
|---|---|---|
| `data/authority/<site>/<uuid>.json` | 药名族 28 条 | 文件散落，无法 SQL 查询/统计 |
| `data/json_envelopes/<site>/*.json` 的 `identifier_resolutions` | 标识符族 31 条 | 只在信封里，数据库无记录 |

数据库侧完全没有记录。论文所称「标准标识符对齐」在存量语料上**没有可入库复查的结果**，也无法支撑跨站点、跨权威源的统计。

A1 把这条通路补上：对齐结果在原链路写库成功后正式入库，文件旁路继续保留（可复查快照）。

## 二、前置：迁移器两个 bug（不修则 V017–V021 无法应用）

服务器带来的 V017–V019 一执行就失败。定位到 `migration/migrate.py` 两处：

**bug 1：按分号硬拆 SQL。** `sql.split(";")` 会把 PostgreSQL 的 `$$ ... $$` 函数体劈开。V019 含 3 个 plpgsql 函数，实测被拆成 61 段、其中 **8 段美元符不平衡**，必然语法错。

改为状态机 `_split_sql()`，只认顶层分号，正确跳过：

- `$tag$ ... $tag$` 美元引用块（tag 可空）
- `'...'` 单引号字符串（`''` 为转义）
- `"..."` 双引号标识符（`""` 为转义）
- `--` 行注释、`/* */` 块注释（支持嵌套）

修复后 V019 从 61 段降到 16 段、全部平衡；10 个边界用例（引号内分号、注释内分号、嵌套注释、tagged 块等）全过。

**bug 2：`text()` 把原生语法当绑定参数。** `conn.execute(text(stmt))` 遇到 `'{"is_deleted":true}'::jsonb` 报 `A value is required for bind parameter 'true'`。改用 `conn.exec_driver_sql(stmt)` 直接下发。

> 这两个 bug 属于服务器改动引入的工具债，但影响所有后续迁移，必须修在 `migrate.py` 而不是绕开。

## 三、表设计

### V020 `doc_authority_resolution`

两族共用一张表，`id_type` 区分：

```sql
CREATE TABLE doc_authority_resolution (
    id               BIGSERIAL PRIMARY KEY,
    uuid             TEXT NOT NULL,        -- 对应 documents.uuid（无外键，沿用软删除风格）
    source_site      TEXT NOT NULL DEFAULT '',
    id_type          TEXT NOT NULL DEFAULT 'drug_name',
    resolution_key   TEXT NOT NULL,        -- 药名族=原始药名；标识符族=字段名
    found            BOOLEAN NOT NULL DEFAULT FALSE,
    degraded         BOOLEAN NOT NULL DEFAULT FALSE,
    skipped          BOOLEAN NOT NULL DEFAULT FALSE,   -- V021 补
    std_id           TEXT,
    source_id        TEXT,                 -- pubchem / chembl / format / whitelist
    raw_value        TEXT,
    resolved_value   TEXT,
    candidate        TEXT,                 -- 药名归一实际查询的候选名
    rule             TEXT,                 -- as_is/cut_descriptor/inner_alias/comma_segment/combo_split
    candidates_tried INTEGER,
    confidence       DOUBLE PRECISION,
    candidates       JSONB NOT NULL DEFAULT '[]',
    is_deleted       BOOLEAN NOT NULL DEFAULT FALSE,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (uuid, id_type, resolution_key)
);
```

设计取舍：

- **一张表而不是两张**：两族的 `found`/`std_id`/`source_id`/`degraded`/`confidence` 语义完全一致，合成后「某文档共对齐多少标识符」一句 SQL 可查；代价是约 4 列对其中一族恒为 NULL。
- **`UNIQUE (uuid, id_type, resolution_key)`**：写入走「先删后插」，整文档替换而非逐行 upsert。原因：药名集合本身会变（这次抽到 3 个、下次 2 个），按行 upsert 会留下上次多余的键。
- **索引分两类**：普通索引供按文档/站点/类型查；`WHERE found` 与 `WHERE degraded` 用**部分索引**——命中率与降级率是两个必须分开报的口径。

### V021 为什么必须补 `skipped`

`skipped` 标记占位名（Placebo / 生理盐水 / 产品包装描述），这类值不送权威库、也不算未命中。没有该列时只能靠 `candidates_tried = 0` 隐式推断，**命中率会算成 21/27 = 77.8%，而正确值是 21/26 = 80.8%**。显式存列后口径可直接用 SQL 复算：

```sql
select count(*) filter (where not skipped)                    as eligible,
       count(*) filter (where found and not skipped)          as matched,
       count(*) filter (where degraded)                       as degraded
from doc_authority_resolution where id_type = 'drug_name';
```

## 四、双写位置与跳过逻辑

```python
# core_engine/storage_writer.py  write_to_database
if success:
    save_lineage(...)                  # 现有
    save_authority_resolutions(...)    # 现有：文件旁路
    # A1 新增：入库
    if publication.get("legacy_cache_retained"):
        logger.warning("正文变化已转版本发布，跳过对齐结果入库以防覆盖旧版")
    else:
        upsert_authority_resolutions(doc_uuid, site, authority, identifiers)
```

**为什么必须跳过版本分支**：`upsert_document` 在正文变化时**不更新 documents 表**，而是返回 `{"legacy_cache_retained": True}` 并把新正文排进 `publication_outbox`（旧正文与旧抽取结果继续挂在原记录上）。此时若照常写对齐结果，**新正文的对齐记录会盖掉旧正文的**，造成证据错配。

其余保护：入库异常只 `warning`，不影响主流程；表不存在（迁移未执行）时 `to_regclass` 检测后警告返回 0，不让写库整体失败。
