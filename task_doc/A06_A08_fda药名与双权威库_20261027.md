# A0.6 + A0.8：fda 药名映射修正 与 双权威库分族

> 编写：2026-10-27
> 前置：A0（药名通路）、A0.5（药名归一）、A0.7（标识符通路）
> 范围：仍在「采集 → 标准化落库」内，不涉及下游 KG

---

## 一、A0.6：fda 的 `drug_name` 到底错在哪

### 1.1 原状况

`config/sites/fda/api_enforcement.py` 的字段映射是单路径：

```python
"drug_name": "product_description",
```

openFDA 召回记录里 `product_description` 是整段包装描述，落库后 `extra.drug_name` 长这样：

```
Ifosfamide Injection 3g/60 mL, Single dose vial, Rx only, Sterile,
For Intravenous Use, Refrigerate at 2-8 degrees celcius,
Distributed by Pfizer Labs, Division of Pfizer Inc., New York, NY 10017,
NDC 0069-4496-22
```

这不是药名，是「剂型 + 包装 + 监管标记 + 企业 + 地址 + NDC」的拼接。

### 1.2 但「截断它」不是解

A0.5 已经做了 `biz_rules/drug_name_normalizer.py`，第一条设计原则写得很明确：

> **不改原值**：`extra.drug_name` 保持采集原样，候选名只用于「查询」，
> 命中后由对齐结果记录 `raw_value` / `candidate` / `rule` 三元组，可回溯。

如果在映射层就把描述截成 `Ifosfamide`，归一器就看不到原文，「哪条归一规则贡献了多少命中」这条论文口径直接失效。所以 A0.6 不能在映射层截断。

### 1.3 真正的缺陷：没有用上原始记录里的结构化名称

openFDA 的记录里本来带 `openfda` 子对象，含四个规范字段：

```json
"openfda": {
  "application_number": ["NDA020779"],
  "brand_name": ["VIRACEPT"],
  "generic_name": ["NELFINAVIR MESYLATE"],
  "substance_name": ["NELFINAVIR MESYLATE"],
  "manufacturer_name": ["AGOURON"]
}
```

问题在于**覆盖率不均匀**：实测 10 条召回记录只有 3 条 `openfda` 非空，10 条说明书只有 1 条非空。单路径映射无法表达「有则用、无则退」，只能二选一——选了 `product_description`，就放弃了那 3 条本来能拿到的规范名。

### 1.4 修法：给 `field_map` 加「候选链」语义

`core_engine/api_router.py::_get_nested` 接受路径列表，按顺序取值、返回第一个非空：

```python
"drug_name": [
    "openfda.generic_name.0",
    "openfda.brand_name.0",
    "openfda.substance_name.0",
    "product_description",          # 兜底：保持原值不截断
],
```

顺序理由：通用名（INN）是权威库命中率最高的写法；品牌名次之；`substance_name` 常与通用名重复，作第三顺位；`product_description` 只作兜底。

这是**通用能力**，不是 fda 特例——任何「同一语义字段分散多处、覆盖率不均」的 API 站点都能用。

### 1.5 副产品：fda 的批准文号通路

fda 此前**没有任何可校验的标识符字段**，A0.7 刚建好的标识符格式校验在这两个站点上是 0 输入。补两条：

| 站点 | 新增 extra 字段 | 来源 |
|---|---|---|
| fda_api_enforcement | `approval_number` | `openfda.application_number.0` |
| fda_api_drug_label | `approval_number` / `product_ndc` / `spl_set_id` | `openfda.*` |

同时 `fda_api_drug_label` 此前**根本不在 `EXTRA_MODEL_MAP`** 里（新增 `FdaLabelExtra` 并注册），意味着它 10 条信封的 extra 从未被任何模型约束过。

## 二、A0.8：为什么必须接第二个权威库

### 2.1 PubChem 单库的缺口

用 A0.5 的归一器 + PubChem 跑完 150 条语料（28 个待对齐药名），结果：

| 站点 | 药名 | 命中 | 未命中 |
|---|---|---|---|
| clinicaltrials | 16 | 5 (31.2%) | 10 |
| fda_api_enforcement | 11 | 9 (81.8%) | 1 |
| fda_api_drug_label | 1 | 1 (100%) | 0 |
| **合计** | **28** | **15 (53.6%)** | 11 |

未命中里有一类特别整齐——**全是生物制品**：

```
Nivolumab / Ipilimumab / Filgrastim / Pegfilgrastim / Etanercept
```

原因不是药名抽取错，而是 PubChem 的 `compound` 库面向小分子：蛋白类药物通常只有 `substance` 记录，没有 compound 记录，按名称查 CID 直接 404。这属于**权威库的覆盖边界**，不是数据缺陷。

### 2.2 为什么选 ChEMBL，以及为什么必须精确匹配

ChEMBL 是 EBI 的生物活性分子库，单抗 / 融合蛋白 / 细胞因子都在里面。预检（2026-10-27）：

| 名称 | `pref_name__iexact` 结果 |
|---|---|
| Nivolumab | 1 条命中 |
| Ipilimumab | 1 条命中 |
| Filgrastim | 1 条命中 |
| Pegfilgrastim | 1 条命中 |
| Etanercept | 1 条命中 |
| **Texas**（假阳性探针） | **0 条** |

关键选择：用 `molecule.json?pref_name__iexact=<name>`（精确名过滤），**不用** `molecule/search`（全文检索）。理由来自 A0.5 踩过的坑——PubChem 的名称检索对单 token 词（`Texas`）会模糊命中并返回无关化合物，制造假成功。生物制品的通用名唯一且规范，精确匹配足够；代价是查不到拼写变体，但「宁记未命中，不记假命中」在论文口径上是必须的。

### 2.3 分族顺序与停表条件

```
drug_name 解析：
  1. PubChem（小分子首选）
     ├─ 命中 → 返回 PUBCHEM:<cid>
     ├─ 降级（网络/限流）→ 跳过 ChEMBL，直接落本地白名单
     └─ 404 确认未命中 → 进入第 2 步
  2. ChEMBL（生物制品）
     ├─ 命中 → 返回 CHEMBL:<id>
     └─ 未命中/400/404 → 进入第 3 步
  3. 本地白名单（仅 8 条，接口不可用时的兜底）
  4. 彻底未命中（区分「查了没有」与「没查成」）
```

**为什么降级时要跳过 ChEMBL**：降级意味着网络或限流故障，换一个库既不会成功，又会把等待时间翻倍，还可能把「两个库都没查成」误记成「查无此药」。这一点与 A0.5 的「降级立即停」原则一致。

限流方面加了 1 秒最小间隔（EBI 建议 ≤1 req/s）与 429/5xx 退避重试一次。

## 三、补的基础设施：药名对齐结果此前从未落盘

A0.8 之前有个隐患没被发现：`data/authority/<site>/*.json` 里 `resolutions` **全是空的**。

原因是 `align_identifiers_offline.py` 只处理「本地格式校验」那一族（NCT / PMID / DOI / 批准文号，零网络）；药名对齐要联网，一直只在一次性探针脚本里跑，结果活在内存里。也就是说：**辅创新「标准标识符对齐」在 150 条存量语料上没有可复查的落盘结果**。

新增 `scripts/align_drug_names_online.py`：

- 复用管线同款 `_extract_drug_names`（含 `;` 拆分）与 `_align_one`（候选回退、命中即止、降级即停、占位零请求）
- 结果写回信封 `authority_resolutions` + `data/authority/<site>/<uuid>.json`
- 分母排除占位名，与 `authority_store.summarize()` 同口径
- 输出归一规则贡献与权威库贡献，供论文做「哪条规则 / 哪个库补了多少」

## 四、数据修复结果

### 4.1 fda 药名重映射（3 条）

只对「原始记录能取到更优来源」的记录改写，取不到的时候候选链自然回落到 `product_description`，结果与现值相同、不产生改动。

| 文档 | 原值（截断显示） | 新值 |
|---|---|---|
| 0fa81856 | `VIRACEPT (R) (nelfinavir mesylate) Tablets, 625 mg, 120-count bo…` | `NELFINAVIR MESYLATE` |
| b975cfbd | `No Drip Nasal Spray, Oxymetazoline HCl 0.05% Nasal Decongest…` | `OXYMETAZOLINE HCL` |
| f2d0943a | `Dextroamphetamine Saccharate, Amphetamine Aspartate, Dextroa…` | `DEXTROAMPHETAMINE SACCHARATE, AMPHETAMINE ASPARTATE, …` |

> 第三条看起来"没变化"，因为该产品的通用名本身就是一个长复方名（四种安非他明盐）。相比原描述，新值去掉了后面的剂量与包装，但仍是复方全名——归一器的 `combo_split` 规则会把它拆成 `AMPHETAMINE ASPARTATE` 等候选继续尝试。这是**诚实的失败**：PubChem / ChEMBL 都没有这个复方，不硬凑。

### 4.2 fda extra 字段

| 站点 | extra 键数/条 | 非空值 |
|---|---|---|
| fda_api_enforcement | 1 → **10** | 10 → **93**（100 个位置） |
| fda_api_drug_label | 0 → **3**（仅 1 条有值，因 openfda 覆盖率 1/10） | 0 → 3 |

`approval_number` 非空：enforcement 3/10、label 1/10。这是 openfda 的真实覆盖率，不是抽取失败。

### 4.3 药名对齐命中率

| 口径 | A0.5 后（PubChem 单库） | A0.8 后（PubChem + ChEMBL） |
|---|---|---|
| 药名总数 | 28 | 28 |
| 排除占位名（安慰剂/盐水） | 26 | 26 |
| 命中 | 15 | **21** |
| **命中率（有效分母）** | **57.7%** | **80.8%** |
| 权威库分布 | PubChem 15 | PubChem 15 + **ChEMBL 6** |

ChEMBL 补上的 6 个：

| 原始名 | 命中名 | 标准标识符 | 归一规则 |
|---|---|---|---|
| Nivolumab | Nivolumab | `CHEMBL:CHEMBL2108738` | as_is |
| Ipilimumab | Ipilimumab | `CHEMBL:CHEMBL1789844` | as_is |
| Filgrastim | Filgrastim | `CHEMBL:CHEMBL1201567` | as_is |
| Pegfilgrastim | Pegfilgrastim | `CHEMBL:CHEMBL1201568` | as_is |
| Nivolumab + Relatlimab | Nivolumab | `CHEMBL:CHEMBL2108738` | combo_split |
| Enbrel (Etanercept) | Etanercept | `CHEMBL:CHEMBL1201572` | inner_alias |

最后两条正是 A0.5 归一规则的价值：`combo_split` 与 `inner_alias` 各贡献 1 次命中，若只按原名送查，这两条都是失败。

### 4.4 仍未命中的 5 个（都是合理负例）

| 原始名 | 原因 |
|---|---|
| JNJ-26866138 0.7 / 1.0 / 1.3 mg/m2 | 临床试验阶段代号，非上市药，两个库都没有 |
| LY4066708 | 同上 |
| Trimix QM10 Papaverine 30 mg/Phentolamine 4 mg/Atropine 1 mg/PGE… | 复方制剂，库里无对应分子记录 |

这些不是抽取缺陷，放宽规则只会制造假命中。

### 4.5 标识符格式校验（含 fda 新增通路）

| 站点 | 文档 | 字段 | 命中 | 命中率 |
|---|---|---|---|---|
| clinicaltrials | 10 | 10 | 10 | 100% |
| pubmed | 10 | 17 | 17 | 100% |
| fda_api_enforcement | 3 | 3 | 2 | 66.7% |
| fda_api_drug_label | 1 | 1 | 1 | 100% |
| **合计** | **24** | **31** | **30** | **96.8%** |

A0.7 时是 24 文档 / 27 字段 / 27 命中；A0.6 让 fda 从 0 输入变成 4 字段。未通过的 1 条是 `M012`（openFDA 的旧式申请号），不符合 `NDA/ANDA/BLA + 6 位` 的现行格式——不放宽正则去凑命中率。

### 4.6 清洗质量审计

| 指标 | A0.7 后 | A0.6/A0.8 后 |
|---|---|---|
| 结构化字段填充率 | 291/481 = 60% ⚠️ | **377/574 = 66%** ⚠️ |
| 失败项 | 3 | **2** |
| 通过项 | 8 | 8 |

失败项只剩两个，都在采集端，清洗层无可修项：

- 必填字段完整性：39 处空缺（标题 23 / 日期 16，`css_extract` 未命中）
- 硬噪音：6 条命中（pubmed 的 HTML 表格，与 `217d55f` 同源问题）

> 填充率的分母从 481 涨到 574，是因为 fda 两个站点新声明了字段。**新字段只有 30% 有值，会把总填充率拉低**——这是诚实的代价：不能靠"少声明字段"来抬高填充率指标。

## 六、测试

| 阶段 | 用例数 |
|---|---|
| A0.7 收尾 | 456 |
| + A0.6 映射测试（15） | 471 |
| + A0.8 ChEMBL 测试（15） | 486 |
| + 既有用例补齐（对齐/落库相关） | **509 passed / 5 xfailed** |

新增用例覆盖的关键断言：

- 候选链：按序取第一个非空 / 全空返回空串 / 混入 `__const__` 仍生效 / 单路径语义不变
- fda 映射：有 openfda 取规范名；无 openfda 兜底且**不截断**（截断是归一器的职责）
- 批准文号：从 `openfda.application_number.0` 取值；`validate_extra` 后仍在；`M012` 不通过格式校验
- ChEMBL：PubChem 命中即短路 / 确认未命中才查 ChEMBL / 降级跳过 ChEMBL / 两库都无 → 有效负例 / 本地白名单排最后
- ChEMBL 查询构造：必须带 `pref_name__iexact`，URL 中不得出现 `molecule/search`
- ChEMBL 限流：429 重试一次；两次都失败则整体降级（不记成「查无此药」）
