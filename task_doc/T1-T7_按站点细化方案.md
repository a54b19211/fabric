## 0. 为什么要"按站点细化"

现有 T1–T7（基线测试 / L3 归一 / 标识符对齐 / 多维质量评分 / 结构化校验 / 字段级血缘 / 质量门禁评估）在实现上都是**一套全局规则**，而项目实际有 20 个站点、5 类截然不同的数据形态。

实测证据：同一篇 300 字正文、同样有结构化字段，不同站点在 T4 五维评分下的结果：

| 站点 | 总分 | 等级 | 权威性 | 准确性 |
|---|---|---|---|---|
| FDA CRL | 0.948 | 高 | 0.95 | 0.80 |
| EMA | 0.948 | 高 | 0.95 | 0.80 |
| PubMed（有 DOI） | 0.925 | 高 | 0.70 | 1.00 |
| CDE 2015 年旧公告 | 0.873 | 高 | 0.95 | 0.80 |
| ClinicalTrials | 0.825 | 高 | **0.30** | 1.00 |
| NMPA 80 字短公告 | 0.557 | **低** | 0.95 | 0.00 |

**ClinicalTrials 是美国官方临床注册库，权威性被判 0.30；CDE 一条十一年前的公告被判 0.95。** 这不是参数调优问题，是规则与站点形态不匹配。

## 1. 站点分族

| 族 | 成员 | 共同特征 | 关键标识 |
|---|---|---|---|
| **A 监管信函/决定** | FDA CRL（拟）、EMA（拟） | 一编号多文档、PDF 原件、有审批状态 | NDA/ANDA 号、EU 产品号 |
| **B 文献** | PubMed、Europe PMC（拟） | 摘要+全文、有更正/撤稿关系、有许可限制 | PMID、PMCID、DOI |
| **C 试验登记** | ClinicalTrials、ChiCTR | 一个试验多个字段、人数字段、预计/实际日期 | NCT 号、ChiCTR 号 |
| **D 中国政务公告** | NMPA、CDE、CDE-信息公开、CDE-指导原则 | 中文短公告、附件、栏目多、翻页 | 公告编号 + 日期 |
| **E 商业/资讯** | Roche、Fierce、DrugBank、HKEX、NCCN、药促会×4 | 长正文、公司公告、指南 | DrugBank ID、UNII、股票代码 |

### C. 药名兜底到整条标题

| 项 | 内容 |
|---|---|
| 位置 | `core_engine/transform_pipeline.py:67` |
| 现状 | `return sd.get("drug_name") or extra.get("drug_name") or parsed_result.get("title") or ""` |
| 实测后果 | 无药名的文档把整条标题送 PubChem：NMPA →「国家药监局关于修订XX说明书的公告」；CDE →「关于某某注射液获批上市的公告」 |
| 拟改 | 删除 `or parsed_result.get("title")`；无药名直接不发起对齐 |

| 副作用 | 部分中文站点药名确在标题中（如 CDE 产品公告），去掉兜底后这类文档准确性维度少拿 0.2 分。取舍：宁可漏，不可错——错误对齐危害大于不对齐 |
| 与服务器改动重叠 | 否 |

### F. 时效性规则与"补档"语义冲突

| 项 | 内容 |
|---|---|
| 位置 | `core_engine/quality_checker.py:85` `_score_timeliness` |
| 现状 | 规则"距今 ≤5 年给 1.0" |

**新发现：字段契约缺口（真实信封无法直接进质检）**

真实信封用 `raw_content` 存正文，而 `check_quality` 读 `markdown`。实测把一条真实 NMPA 信封直接喂入：

```
总分 = 0.557  等级 = 低
维度 = {completeness: 0.2, accuracy: 0.0, timeliness: 1.0, authority: 0.95, consistency: 0.8}
问题 = ['Markdown 过短(0字符 < 100)', '缺少结构化字段(structured_data 为空)']
```

**正文实际有 651 字符，被读成 0 字符。** 说明：① T1 若要用真实信封做 fixture，必须先建立 `raw_content → markdown` 的显式适配（不能隐式假设两字段等价）；② 该缺口同时暴露"同一份资料在不同环节字段名不一致"的契约风险。
