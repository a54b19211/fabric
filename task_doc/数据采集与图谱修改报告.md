## 2. 现在资料怎样到达雷达

```text
原有采集、上传、清洗
        ↓
原采集库提交资料，同时记下“还有哪些变化需要发布”
        ↓
发布程序把原文及元数据保存为固定版本
        ├─ 正文版本 → 雷达读取、筛线索、开展调查
        └─ 实体/关系审核或身份资格变化 → 图版本 → 雷达找关联和查原文
```

正文可以先供雷达使用，不必等图谱建完。唐蔚雯补充对象身份和关系后，同一个调查可以继续使用这些信息。

两边职责如下：

| 工作 | 负责方 | 交出去的结果 |

## 4. 徐子雯这边需要掌握的变化

### 4.1 一份资料有三个不同状态

```text
原库保存成功 → 原文版本发布成功 → 雷达已经读取
```

它们不是同一件事。原库有记录，但发布因体积超限失败，雷达就还没有采用它；发布成功但雷达尚未追到这个位置，也不能报“已经进入分析”。

原采集库新增 `publication_outbox`，可以理解成“待发布清单”。资料和待办在同一次事务里提交。发布程序先保存固定输入，再向历史库写版本，最后确认源待办。历史库已成功而源端确认失败时，下次核对原回执，不重新抓一次可能已变化的网页。

这不是两个数据库之间的原子事务。需要恢复的中间状态仍存在，只是已经有记录可查。

### 4.2 新正文不会悄悄覆盖旧证据

同一个 UUID 的正文由甲版变成乙版时，新内容先进入版本链，旧页面仍挂着甲版抽取结果时，兼容缓存保留甲版。返回值中的 `publication_pending`、`legacy_cache_retained` 说明了这一点。

因此，后续要把“重新采集”和“采用新正文重新抽取”分成可核对的动作。未经确认，不能把旧实体、旧关系、旧引文直接挂到乙版正文上。

连续重复没有必要产生新版本；甲→乙→甲或撤回后恢复则须保留观察过程。即便原文内容相同，也不能把版本数当成独立研究数。

### 4.3 目前能用哪些来源

| 来源 | 已实现的接入 | 现役范围与限制 |
|---|---|---|
| NMPA、CDE、CDE 信息公开、ChiCTR、FDA 标签、FDA 召回、ClinicalTrials 旧库存 | 按来源许可，从原库连续发布正文和版本 | 共用 `legacy_documents` 桥接来源；各站目录项为 0，不等于该站没有进入桥接库。补录仍未全部完成 |
| ClinicalTrials 公开 API | 有范围的真实读取、登记原始字段和版本保存 | 尚未加入当前持久续页的常驻刷新；不能据一次查询称已监控全部临床登记 |
| Europe PMC | 元数据、摘要、更正关系与按更新日期续页 | 当前常驻查询是 `BCMA AND myeloma`，不是全部医学论文；不自动取得全文 |
| WHO DON | 官方通报原件、发布/更新时间、续页和固定窗口刷新 | 当前跟踪最近 30 天的公告更新；选择性公告不等于疫情全量 |
| FDA CRL | 有范围的公开信函读取和固定原件 | 曾在隔离环境实取验证，当前现役目录尚无该来源采用版本，不等于已常驻采集 |
| PubMed | 原采集器摘要与更正关系读取修复，历史公开读取入口 | 当前未列入现役历史来源许可和常驻刷新配置；不能写成已连续接通 |
| 外部历史档案、商业或公共卫生指标 | 有受控导入和逐字段原件绑定入口 | 还没有真实近十年管线档案、持续企业财务或同口径病例数据 |

当前公开 API 读到旧年份论文，只能证明今天读到了它，不能证明系统在当年就已经知道。外部历史档案需要单独的出处和审核记录，不能把导入时间改成发表时间。

## 5. 唐蔚雯这边需要掌握的变化

### 5.1 没有替你重做图谱，增加的是可靠交付接口

雷达现在可以从固定图版本里找名字、处理歧义、选种子、取邻居、读对应原文。已有 `entity_dict`、`extracted_entities`、`entity_relations` 和审核成果继续使用，没有新建另一套实体消歧库。

主要新增内容：

- 字典对象、文中提及、PrimeKG 节点使用不同命名空间；未对齐的 mention 不能伪装成已确认字典对象。
- 同名可以返回多个候选，不自动选第一个；当前别名和合并结果不倒填到旧版。
- 关系保留原类型和方向。查入边时也不把原边方向翻转，图的方向不自动解释成因果。
- 原文绑定精确到资料版本、引文和字符位置。自动发布还要求引文在目标清洗正文中唯一匹配，缺失或出现多处时保持未绑定。旧图 CLI 捕获入口仍取首次匹配，重复句处理尚须按第 8 节补齐，不能把两个入口都写成已完成唯一性检查。
- `approved`、`auto_approved`、原文绑定和专业证据评价分开。自动审核不能写成人工确认，人工审核也不等于机制评价。
- 文档撤回、审核撤销、字典资格变化可以触发新的图版本；旧图保留，供已有调查复查。

正文变更是逐次冻结的。图审核变化目前记的是“图需要重新发布”，多次中间变化可能归并为发布时的当前状态，不能据此声称已有完整的逐次审核历史。

### 5.2 时态能力还需要唐这边继续做

现在能回答“系统在这个采用时点已经保存了哪些图资料”，还不能普遍回答“这条研发或授权关系在现实中从哪一天到哪一天有效”。

关系真实有效时间未知就留空；不能拿文档发布日期或图的导入时间补齐。药物、适应证、试验登记、研发项目、企业授权之间的谱系仍需核实，不能把同名药物或同靶点项目直接合为一个。

PrimeKG 已有只读捕获及固定图包入口，可以作为追问方向。它不会自动持续发布整个 Neo4j 图，也不提供过去十年关系快照。当前边不是新论文证据，不能直接算作新进展、临床有效性或合作关系。

源库虽然已有审核人、审核时间和合并日志，新图发布链还没有完整带出这些信息：旧图转换主要传了审核状态，HTTP 捕获和自动发布中的合并日志目前为空。这是明确的接续任务，不能写成身份合并、回滚和审核沿革已经全部贯通。

既有真实联调中，一组旧临床资料只有 5 个自动审核、身份未确认节点，0 条关系；真实 PrimeKG 背景另引出了临床检索。已核关系进入计算的例子使用明确标注的教学材料，不能当成已有一批真实人工审核关系。

旧 WeKnora 写入路径本轮保留。既有身份回退、来源字段保留和隔离问题仍要单独处理；检索出文档片段不等于已经提供带版本与原文证据的图关系接口。

| 出问题的部分 | 优先处理 | 必须保留或核对 |

| API/抽取保护 | 先停止受理和 Worker，核清排队及在途任务 | 不能恢复“启动即清队列”的旧行为来消除异常状态 |

保留新增表和原始版本通常比反向删表安全。整库恢复只用于明确的数据恢复，需要先保存当前新增数据，不能把昨天的数据库副本直接盖到今天的业务库。

### 资料怎样进入 WeKnora

原件保存成功后，现有发表进程扫描已提交版本，把“哪一版资料进入哪个知识库”记入数据库，再调用 WeKnora。仍用原发表循环，没有另建任务平台。

原件保存、上传、解析、向量就绪、来源绑定分别记录。上传成功不等于已经可检索。编号、版本或摘要对不上，不能标成就绪。

超时后先查同一发布编号，再由 WeKnora 幂等入口恢复，不直接重复上传。新版本替代旧版、撤回或配置取消后，旧索引进入清理，旧原件保留。清理要等解析结束且向量已排除，之后仍定期核对，防止迟到写回。

普通发布连续失败会停止自动重发，等待检查后恢复。清理连续失败后每小时核对一次，服务恢复后继续停用，不能把失败说成已撤回。
