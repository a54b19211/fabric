本周需求：熟悉代码的爬，存流程。

先解释一下现在想做什么：可以理解为我们要做的是药大版的deepseek。也就是说，我们需要一个能回答专属问题的大模型（比如hhp这几天干了什么，你问deepseek他肯定是瞎编的，但是如果我们事先把hhp这几天的行程告诉ai，那么别人再问的时候，就会得到正确的答案）

当然我们不是真的关心hhp这几天做了什么，但是问题是存在的，就是怎么让ai来回答专属问题。那答案就是提前把专属问题录进去（具体实现方式可以先不考虑，但是数据是一定要准备的）

那么数据从哪来，就要通过爬虫去爬。

爬虫的思想很简单，就是既然我可以通过浏览器去访问这个页面，那我也可以通过程序去访问这个页面，只是说经过浏览器的渲染，展示给我们的是人类可读的界面，但是实际上我们并不关心这个界面长什么样（这是领导该关心的事情），我们只关心页面里的数据本身。

那么问题就又来了，因为浏览器是需要对数据进行渲染，以展示人类可读的页面，所以除了数据本身，必然会有其他的东西来包着数据，来控制它的显示。一般我们看到的都是html页面

比如页面想展示 我想挣钱，他不能只返回一个 我想挣钱，他得返回一个 <p>我想挣钱</p> ，这个<p></p>就是告诉浏览器怎么渲染 我想挣钱 这四个字的

但<p></p> 又不是数据，因此我们需要把它去掉，也就是清洗。此外，页面上可能还有很多没有用的信息，也是需要清洗的，比如广告信息。

爬本身是需要成本的，因为不是所有网站都大公无私，他们展示的数据不太希望你很轻易地获得，所以有的网站会有比较严格的限制（虽然都可以通过技术手段打破限制）

然后这周要做的，就是大概熟悉一下现在是怎么爬的。


----------------------------------------------------

整个流程分三条线，用大白话说：

第一条线：网页采集

程序从配置文件里读出所有站点，每个站点有一个或多个起始 URL。对每个起始 URL，先把所有列表页都翻出来，从列表页里提取每一条详情页的链接。然后逐条去爬详情页，爬完之后解析内容。

解析有两种路径：如果这个站点配了专属的解析函数（特解），就用 CSS 选择器直接从 HTML 里抠出标题、日期、正文；如果没配，就用 Trafilatura 把 HTML 转成纯文本，再丢给 Qwen 大模型让它提取结构化字段。

详情页里如果有附件链接，还会把附件下载下来。PDF 附件会走 MinerU 云端 API 转成 Markdown，再用 Qwen 提取结构化信息。doc/docx 目前只下载不解析。

每条数据解析完之后，做质量检查：Markdown 太短、或者结构化字段填充率太低的，扔进隔离区；通过的写三份文件——Markdown 全文、JSON 元数据信封、原始文件（PDF 在下载时已经落盘了）。

第二条线：本地 PDF 批量处理

扫描配置里指定的本地目录，找出所有 PDF 文件，每个文件走同样的 MinerU → Qwen → 质检 → 落盘流程。和网页采集的区别只是来源不同，后半段完全一样。

第三条线：导出审核 CSV

把质检通过但置信度低（C 级）的数据导出成 CSV，供人工审核。

贯穿全程的两件事

一是置信度打分：每条数据落盘时都会根据来源 URL 是不是官方站点、有没有 DOI、有没有期刊名，打一个 A/B/C 的置信度等级，写进 JSON 信封里。

二是幂等性：UUID 是基于 URL 或文件路径生成的，同一条数据重复跑不会产生重复文件，PDF 如果已经下载过也会跳过。

mode=all：三条全跑
mode=crawl：只跑网页采集（第一条）
mode=local：只跑本地 PDF（第二条）
mode=export_review：只跑导出 CSV（第三条）
