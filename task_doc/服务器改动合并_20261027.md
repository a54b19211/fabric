## 三、冲突解决（2 处）

### 3.1 `core_engine/storage_writer.py`

两侧改动落在同一函数 `write_to_database` 上，语义不冲突，取并集：

| 项 | 本方（A0–A0.8） | 服务器侧 | 合并结果 |
|---|---|---|---|
| `authority_resolutions` 字段 | 新增 | 无 | **保留本方** |
| `data/authority` 旁路存档 | 新增 | 无 | **保留本方**，并挪到「写库成功后」执行 |
| `authority_*` / `identifier_*` 统计 | 新增 | 无 | **保留本方**，两套口径分开计数 |
| `upsert_document` 返回值 | 不检查 | `result is False` 视为失败，并捕获 `publication` | **采纳服务器** |
| 血缘落盘时机 | 写库前无条件执行 | 写库成功后才执行 | **采纳服务器** |
| 本地文件存储 | 仅看配置开关 | 需 `success` 且配置开启 | **采纳服务器** |
| 返回值 | 六个统计字段 | `**publication` | **两者并列**，`**publication` 置末防覆盖 |

**附带修复一处真实缺陷**：`_accepts_value` 原先用 `ann is int` 精确比对注解，
服务器把 `enrollment` 从 `int = 0` 改成 `Optional[int] = None`（语义为「未知不补零」）后，
合法的 int 值会一路落到「只接受 list/tuple」的分支被判为类型不符而丢弃。
合并后 `test_merge_fills_clinicaltrials_structured_fields` 立即报
`KeyError: 'enrollment'` 暴露了它。已新增 `_unwrap_optional()` 解包
`Optional[X]` / `X | None`，并补上 `bool` / `float` 分支。

### 3.2 `biz_rules/extractors/pubmed/pubmed_fetcher.py`

冲突点在 `_build_result` 的 `structured_data` 尾部，纯粹是两侧各加了自己的字段：

- 本方：`pmid` / `doi` / `journal_name` / `authors`（落库时由 `_merge_site_fields`
  补进 extra，T3 标识符对齐依赖它们）
- 服务器：`publication_types` / `correction_links`（来自新增的 EFetch 解析）

合并结果：六个字段全部保留。

## 六、架构层面的影响（需在论文中同步）

服务器带来的不只是补丁，而是一套**与现有链路并行的新架构层**：

```
       （本方链路）  content_cleaner → storage_writer → repository.upsert_document
       （服务器链路）CollectedDocument(schema v1) → db/history.py → db/publication.py(outbox)
                          ↑ biz_rules/{collected_document,history_models,reviewed_graph,clinical_research}.py
```

关键点：

- `biz_rules/collected_document.py` 定义了 `datafabric.collected.document.v1`，
  字段包括 `source_doc_uuid` / `original_raw_content` / 冻结时间等，
  由 `db/publication.py` 与 `db/history.py` 消费。
- `217d55f`「HTML 表格不进入挖掘文本」的落点是**这条新链路**
  （`collected_document.py` + `publication.py`），**不是**我们的 `content_cleaner`。
  因此它不会改变存量 150 条信封的审计结果（实测审计仍为 2 失败 / 3 警告 / 8 通过）。

这意味着：论文中「落库」这一环现在有两套表述并存的可能，需要明确以哪条为主链路描述，
否则会出现「同一功能两处实现」的质疑。建议在写第 3 章架构时，先确认
`CollectedDocument → publication` 是否要取代 `storage_writer`，还是作为其上的版本化层。
