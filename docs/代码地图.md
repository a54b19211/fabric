# 代码地图：一篇资料从网站到雷达

以 NMPA（国家药监局）网站上的一篇公告为例。方框里是“文件 · 函数”，箭头右边是写进的表。
其他来源只在“抓”这一段不同（见最后）。

```text
抓 fetch/ ─────────────────────────────────────────────────────────────────────────────────────────
  run/scheduler.py · main                       每隔几秒一轮
    └ fetch/source_refresh.py · refresh_once    到点的来源建一条采集任务             → fabric_runs
                                                每个来源刷新计划的进度               → fabric_source_watches
        └ fetch/fetch_job.py · enqueue_fetch    放进 Redis 队列 extraction
  rq worker（采集工人）
    └ fetch/fetch_job.py · run_fetch_job        取任务、读来源、存版本
        └ fetch/sources.py · read_public        按来源目录 fetch/catalog.py 写的读法调读取函数
            └ fetch/site_crawler.py · read_site 网站来源；站点知识在 fetch/sites/nmpa.py
                ├ fetch/pagination.py · make_driver().iter_detail_urls   翻列表页，拿详情页网址
                ├ fetch/web_client.py · fetch_page                        打开详情页
                ├ fetch/page_parser.py · route_webpage                    取标题、日期、正文
                │   └ fetch/extractors/nmpa.py · extract_nmpa_detail      NMPA 详情页的专门提取
                └ fetch/web_client.py · download_pdf                      附件原件按 sha256 落盘（同一文件只存一份）
            每个请求都用 fetch/transport.py · get（按站点间隔限速、超时、429 重试）；读几条在读取循环里数

存 store/ ──────────────────────────────────────────────────────────────────────────────────────────
    └ store/records.py · finish_fetch → _publish
          · fetch/projection.py · project_record  从原件取标题、发布时间、事实字段（投影，纯函数）
          · store/records.py · fingerprint        原件的内容指纹；和这条记录的当前版本比：
                                                  相同 → 不存；不同 → 新版本，旧版本 replaced_by 指向它
                                                  → fabric_versions（每个版本一行，原件只追加）
                                                  → fabric_attachment_links（附件挂在哪个页面版本下）
                                                  → fabric_runs.coverage（这次读到哪、为什么停）
          连续 3 条“已存且没变”（store/records.py · stored_unchanged）就停：定时刷新只读新的

洗 clean/ ──────────────────────────────────────────────────────────────────────────────────────────
  run/clean.py · main（--loop）
    └ clean/clean_stage.py · process            用 FOR NO KEY UPDATE SKIP LOCKED 领一批没洗过的版本
        ├ clean/clean_text.py · clean_markdown  删导航和模板行、规范空白，记每段偏移 → derived_clean_text
        │   （按字段拼的正文——临床登记、openFDA 说明书和召回——每个字段一节“## 字段名”，知识库按节分块）
        ├ clean/identifiers.py · extract        国药准字、NCT、DOI…                 → derived_identifiers
        ├ clean/profile.py · profile            资料类型、证据类别、正文全不全       → derived_profiles
        ├ clean/registry_changes.py · record_versions  临床登记和上一版逐字段比   → derived_registry_changes
        └ store/index_publication.py · enqueue_versions  同一事务里登记“送知识库”   → index_publications
  小标题规则（NMPA 页面和附件同一套）：clean/headings.py（编号样式定级别、加粗问句、附件分隔行、私用区字符）；NMPA 附件清洗正文只有一个 # 标题（附件名 + 所属公告、文号、日期，知识库每块的标题路径都带它）：clean/clean_stage.py · attachment_with_parent
  run/attachments.py → clean/derived_text.py · process → clean/attachment_parse.py（v5：PDF 先读文字层 clean/pdf_text.py（表格按格读），扫描件才交 MinerU；Word 本机读 clean/office_text.py（编号、标题、合并格）；Excel clean/excel_parser.py；结果过 tidy、完整性对照，不全记 incomplete）→ derived_text

存进知识库 ─────────────────────────────────────────────────────────────────────────────────────────
  run/index.py → store/index_publication.py · run_worker → work_once（一个循环，没活就睡几秒）
        一条待办 = 一个知识库里一条记录的一份正文（同一条记录正文相同的版本、处理器升级后没变的正文，都共用一条）；
        目标写了 limit 的只收那么多条记录（抽样）；ClinicalTrials 的地点名单和结果表、港交所的列表行不进知识库
    └ store/weknora_index_client.py           经桥接服务上传清洗正文 → WeKnora，knowledge_id 写回 index_publications
      └ weknora/app.py → weknora/service.py   桥接服务本身（独立进程 18564）：经 WeKnora HTTP API 上传/停用，只读查 WeKnora 库核向量；回执在 SQLite（weknora/storage.py）

雷达从哪读 api/routers/fabric.py（只走 HTTP，前缀 /api/fabric）──────────────────────────────────────
  GET  /sources                 store/source_listing.py · listing                来源和雷达读的五项能力
  GET  /records, /versions/{id} store/records.py · list_records, read_version   原件、投影、时间
  GET  /changes                 store/records.py · list_changes                  新版本流（after=发布序号）
  GET  /version-differences     store/records.py · version_differences           每个版本的上一版
  GET  /clean-text              clean/clean_stage.py · for_versions               清洗正文和段落偏移
                                （加 quality=true 另带质量等级 clean/profile.py · quality_level：route=quarantine→隔离、
                                 weak_signal→低、normal 里格式 ok 且来源可信度已知→高、其余→中；Atlas 门槛用，雷达不加）
  GET  /derived-text            clean/derived_text.py · for_versions              附件正文
  GET  /registry-changes        clean/registry_changes.py · for_versions          临床登记逐字段差分（清洗时写）
  POST /search                  store/retrieval.py · search（WeKnora 召回，Fabric 逐条核对此刻可见的版本）
  GET  /source-health           fetch/source_refresh.py · source_health           各来源刷新计划的进度
  POST /fetch → GET /runs/{id}  雷达点名补抓：同一条 run_fetch_job 链
  POST /archives                store/records.py · import_archive（场景回放的历史原件，存法和抓取一样）
  GET/PATCH /admin/sources      fetch/source_admin.py · list_sources, set_switches  来源开关（管理员口令；派活只抓两个开关都开的来源）
```

别的来源只换“抓”的那一格：`fetch/sources.py · read_public` 按来源目录里的读法分到

- 接口站点（openFDA、港交所、NCCN、Roche、bioRxiv/medRxiv、arXiv、SEC filing、RSS 新闻稿、EMA…）：仍是 `fetch/site_crawler.py`，
  拉取函数在 `fetch/sites/<站点>.py` 的 `api_fetcher`，每条 `yield fetch.api_fields.record(...)`；
- ClinicalTrials、Europe PMC、FDA 完整回应函：`fetch/sources.py` 里的公共接口读取（投影在 `fetch/projection.py`）；PubMed：同文件的 `_read_pubmed`（全文 `fetch/pubmed_fulltext.py`）；
- WHO 疫情通报 `fetch/who_don.py`、GDELT 新闻 `fetch/gdelt_news.py`、SEC 财报 `fetch/sec_xbrl.py`；本地文件 `fetch/local_files.py`。

之后的“存”和“洗”所有来源都一样。表结构在 `store/migrations/versions/`（`python -m store.migrations.runner --db fabric --apply`）。
图谱是另一个项目 Atlas，不在这个仓库；旧的图包版本（reviewed_graph、primekg_graph）按 `/versions` 照常读，不再能导入。

## WeKnora 桥接服务（weknora/）

把 Fabric 的固定版本发布到 WeKnora，并给出文档特征和检索回执。WeKnora 本身用官方镜像（部署仓库 a54b19211/ZK-radar-deploy 的 weknora/）；
桥接只调 WeKnora 的 HTTP API（上传、改元数据、取消解析、禁用分块），向量只在 WeKnora 库的强制只读事务里读，不碰 Neo4j，
所有上传关闭自动抽图、自动问题和逐篇摘要（`summary_enabled: false`：知识库里不放模型写的内容）。上传的文件名是真实标题
（WeKnora 把它放在每个分块的向量文本前面），内容就是清洗正文本身（契约 v2 起不再加注释行）。重试由 Fabric 的索引程序（run/index.py）负责。

- 运行：`WEKNORA_KDD_CONFIG=<私有 runtime.json> python -m uvicorn weknora.app:app_factory --factory --host 127.0.0.1 --port 18564 --workers 1`
  （正式用 `ops/systemd/datafabric-weknora.service`）；测试 `tests/test_weknora_bridge*.py`。只监听回环地址，单副本。
- `runtime.json`（600 权限，不进 Git）：`token`、`upstream_url`（WeKnora app，默认 `http://127.0.0.1:8080`）、`upstream_api_key`、
  `db`（WeKnora 库的 psycopg 参数，账户只读，15 秒语句超时）、`models`、`journal_path`（SQLite 回执库，持久保留）、`allowed_kb_ids`、
  `source_mappings`（`{source_instance, source_id, knowledge_base_id, scopes}`，每次授权重读）、可选 `demo_kb_ids`。
- 接口（`Authorization: Bearer <服务令牌>`；字段和错误码见 `weknora/contract.json`）：
  `POST /api/v1/kdd/publications` 发布一个固定版本（同版本重放返回同一 knowledge_id，内容不一致 409）；
  `GET /api/v1/kdd/publications/{id}` 状态（所有文本块确有启用向量才 ready）；`POST /api/v1/kdd/features` 1–100 个版本的文档向量
  （启用的原始文本块向量逐块 L2 归一后求均值再归一）；`POST /api/v1/kdd/search` 召回候选（不重排）；`POST /api/v1/kdd/rerank`
  对已核过的 1–60 段重排；`POST /api/v1/kdd/publications/{id}/disable` 撤回。
- publication_id 是 `[knowledge_base_id, source_instance, source_id, source_record_id, version_id]`（可再加 artifact_key、piece）规范 JSON
  的 SHA-256。发送前先记回执；丢响应时按上传 metadata 里的 publication_id 在 WeKnora 库里找唯一条目，找不到就 409 留 unknown，
  不盲目重发。同一个知识库里内容一模一样的另一条发布，WeKnora 当重复拒收（409）。
- 模拟实验（`is_demo=true`）只能用登记在 `demo_kb_ids` 的空 KB，真假互不可见。
